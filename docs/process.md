# Development Process

This is a **solo project run with an adapted Scrum process**. Scrum is a team framework, so it has been adapted openly rather than role-played.

## What's kept
| Practice | How it's done here |
|---|---|
| Product backlog | GitHub Issues written as user stories with acceptance criteria |
| Sprints | 2 weeks each, tracked as GitHub Milestones |
| Sprint planning | `docs/sprints/sprint-XX/plan.md`: a sprint goal + chosen issues |
| Sprint review | `review.md`: what was done, what wasn't, demo notes |
| Retrospective | `retro.md`: what went well, what didn't, one change for next sprint |
| Definition of Done | [`definition-of-done.md`](definition-of-done.md) |
| Board | GitHub Projects: Backlog → Sprint → In progress → In review → Done |

## What's dropped, and why
| Practice | Reason |
|---|---|
| Separate roles (Product Owner, Scrum Master, Dev Team) | One person holds all of them |
| Daily standups | Nobody to sync with; the board shows status instead |
| Story points | Estimates are in rough days; velocity tracking adds little for one developer |

## Documentation budget
Paperwork takes **no more than ~15% of a sprint**. Each review and retro fits on one page. A document nobody would read doesn't get written.
