# 0001. Use an adapted Scrum process for a solo project

- **Status:** Accepted
- **Date:** 2026-10-26

## Context
The project should be run like real software development, with a visible process. It has one developer, and the requirements will change as the developer learns web development.

## Decision
Use Scrum adapted for one person: 2-week sprints, a backlog of user stories, and written planning, review and retrospective documents. Team roles, daily standups and story points are dropped. Waterfall was rejected because it needs fixed requirements and a full design up front, which isn't realistic while learning the stack.

## Consequences
- Progress is visible in small, finished increments
- Retrospectives give a record of what was learned
- Documentation must be capped (~15% of a sprint) so it doesn't replace building
